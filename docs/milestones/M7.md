# M7: Showcase polish

Everything that turns the working app into a portfolio piece: a Glance widget, adaptive layouts, Baseline Profiles with Macrobenchmark numbers in the README, a complete screenshot matrix recorded on Linux, an accessibility pass, structural `FLAG_SECURE`, chat retention with a synced household policy, a readable chat export, and the small items earlier milestones deferred here. Base: `main` after M6.

Constraints that shape the design:
- The home screen is not `FLAG_SECURE`: a widget shows kid data only on that kid's linked phone (D-M7-1).
- Message documents are immutable under the rules; retention therefore deletes locally on every device and asks the server to prune (Admin SDK) through a device-proof-signed callable (D-M7-8).
- Release variants start at onboarding and require a functions URL; benchmarks need a seeded, offline household (D-M7-3).
- Goldens recorded on macOS differ from Linux renders; M7 re-records every golden on Linux through the existing workflow and makes Linux the source of truth (D-M7-4).

## 1. Household policy v2 (schema v8, rules, server)
`household_policy` gains `chatRetentionDays: Int?` (null = keep) and `dailyGameCapMinor: Long?` (null = default 50): Room column + `MIGRATION_7_8` + `8.json`, `HouseholdPolicyPayload`, `firestore.rules` `householdPolicyPayload` key set with bounds (`1..3650`, `0..10_000`), `server/src/config.ts`, emulator tests. `LedgerPolicySource` reads the cap from the policy so every device projects the same exclusions (ADR-0009). Parent-only writes as today.

## 2. Retention and pruning
- `PruneChatUseCase(now)`: deletes local `messages` older than `chatRetentionDays` (by `createdAt`), their blob cache entries and `read_marks` older than the cut; keeps `message_seq` and `thread_keys`. Runs daily (`PruneChatWorker`) and after each successful sync on every device; "Delete chat history now" = days 0 for the household (sets a one-off `chatPurgeAt` marker in the policy? No: a parent action `purgeChat` calls the server and local prune with `before = now`; D-M7-8).
- Server `pruneMessages` callable (device proof, PARENT only, rate-limited): deletes `messages` and `blobs` chunks older than `max(policy days, 1)` days or before an explicit instant ≤ now; writes an audit `prunes/{id}` doc (counts, no content). Rules unchanged for clients; Admin SDK bypasses them. A parent device calls it after its local prune when it holds the newest policy.
- Pull after prune: cursors move forward only; a device whose cursor predates the prune simply never sees deleted rows (D-M4-10 covers re-links).
- Settings: Data section gains "Keep chat messages for: Forever / 30 / 90 / 365 days" and "Delete chat history now" (typed confirmation, parent-authorised). PRIVACY.md and CONTROLS DP-7 updated.

## 3. Export v2
Device-side plaintext chat export, parent-authorised (biometric/PIN), added to the existing zip: `chat/<kidId>.json` (messages decrypted locally: time, author role, kind, text/preset, blob file name) and `chat/media/*.jpg|.m4a` from the blob cache (fetching missing blobs is best effort, listed in `chat/missing.json`). `exportHousehold` server export stays as is (ciphertext). D-M7-9; PRIVACY promise closed.

## 4. Widget (`widget/`)
Glance `GlanceAppWidgetReceiver` + manifest + `appwidget-info` (2×2 and 4×2, resizable, preview). Content on a linked kid phone: kid name, fiat balance (tier-formatted), minutes, chores due today (count + first two titles), tap opens the app. Elsewhere (parent phone, no session, removal pending, sign-in-again): "Open Sprout" only. Data through a Hilt `WidgetEntryPoint` in `app` over a new `core/database` `KidTodaySummaryUseCase` (extracted from `KidTodayViewModel`'s today computation, which then uses it). Refresh: `WidgetRefresher` called from `SyncReportProcessor` after a successful sync, after local ledger/chore writes (Room invalidation observer in `AppInitializer`), from the time bank stop, and a 6 h periodic fallback. Tests: Glance `runComposition` unit tests for the three states; `KidTodaySummaryUseCase` tests. ADR-0012 "Widget data exposure".

## 5. Adaptive layouts
`androidx.compose.material3.adaptive` + `window` size classes. `core/ui`: `LocalWindowWidthClass`, `rememberWindowWidthClass()`, `ContentWidth(max = 640.dp)` wrapper applied to every scrolling screen; parent list-detail panes on Expanded for settings (hub + section), chat (threads + thread) and chores (list + editor) using Navigation 3 `ListDetailSceneStrategy`; parent dashboard two columns on Medium+; shop/games/memory grids with adaptive column counts; Seedling touch targets unchanged. `ScreenshotDevice.TABLET` (1280×800 dp landscape, 1.0 density class) and `captureWidthClasses(name)` for: parent home, settings hub, chat threads, chores list, kid wallet (per tier), games hub (per tier). D-M7-2.

## 6. Baseline Profiles and Macrobenchmark
- `benchmark` build type in `app` (initWith release, `isDebuggable = false`, signing debug, `BuildConfig.BENCHMARK = true`): seeds the demo household (as debug does), skips the functions-URL check with a placeholder, disables sync and App Check. `checkReleaseConfiguration` unaffected.
- Journeys in `benchmark/`: cold start to the parent dashboard (demo PIN entered via UiAutomator), kid wallet scroll, chores today, games hub → arithmetic round; `BaselineProfileGenerator` covers them; `StartupBenchmark` (None vs Partial) + `ScrollBenchmark` (`FrameTimingMetric`).
- Generate on a local emulator (`generateBaselineProfile` with a connected device); commit `app/src/main/generated/baselineProfiles/baseline-prof.txt` and `startup-prof.txt`. Record startup P50/P90 with and without the profile in README "Performance" (device, date, APK size). No CI device job; a manual `benchmark.yml` with a GMD is documented as optional. D-M7-3.

## 7. Screenshot matrix and Linux goldens
`docs/SCREENSHOT_TESTS.md` gains the screen × tier × state table (the single source) and the rule "parent screens light+dark, kid screens per tier light, plus one dark golden per kid screen family". Fill the gaps the survey lists: `app/` gets the screenshot plugin (KidPicker, SignInAgain + erase dialog, Removed, StartupError, shortcut bars); settings sub-screens (kids, allowance, savings goals, about, link states, security dialogs, reauth, export in progress, retention row, AI row), lock exit gate, onboarding steps (signing setup, household, kid add), kid today loading/error/empty/submit sheet/propose sheet/rejected per tier, kid wallet loading/error/history-empty/savings goal/"Not counted" per tier, shop loading/error/empty/confirm/outcome per tier + parent view, chat kid dark variant, time bank dark variant, widget (Glance preview rendered through a Compose host). Last step of M7: run `record-screenshots.yml`, download the artifact, commit every golden, and set the doc rule that only Linux records (D-M7-4).

## 8. Accessibility pass
`core/testing` `AccessibilityRule`: walks the semantics tree of a screen and asserts every clickable/toggleable has text or a content description, no two identical descriptions among siblings, touch targets ≥ the tier minimum, no `clearAndSetSemantics` hiding interactive nodes; applied in every feature's screen test. Fixes: `PinPad` digit buttons and backspace announced, `BalanceJar`/`MinutesSun`/`SavingsStars` described with the value, chat voice recorder/player states announced, memory and counting per D-M5-22, colour-only states get text/icons, heading semantics on every screen title, live regions reviewed. Font scale 2.0 goldens for parent home, kid wallet (per tier), chat thread (`fontScale` qualifier). `docs/ACCESSIBILITY.md` checklist. D-M7-5.

## 9. `FLAG_SECURE` structurally
`SproutApp` applies `SecureWindow()` at the root of `ParentArea`, `KidArea` and `OnboardingArea` (link code is a credential; kid screens show names and balances); dialogs/sheets inherit. Robolectric test asserts the flag in each area and on the splash. `RequireParent` keeps its own call. THREAT_MODEL T15 → Implemented (structural enforcement instead of a lint rule), CONTROLS DP-9 updated. D-M7-6/7.

## Decisions
D-M7-1 widget shows kid data only on that kid's linked phone; D-M7-2 adaptive scope (content width cap everywhere, list-detail for three parent flows, dashboard columns, adaptive grids); D-M7-3 benchmark build type with seeding and placeholder backend; committed profiles; numbers in README; no CI device job; D-M7-4 Linux goldens become the source of truth at the end of M7; D-M7-5 accessibility rule in every screen test + font-scale goldens for a subset; D-M7-6 kid area and onboarding are FLAG_SECURE; D-M7-7 structural enforcement instead of a lint rule; D-M7-8 retention = local prune on every device + server prune callable; D-M7-9 plaintext chat export from the device, parent-authorised, best-effort media; D-M7-10 game cap and retention live in the synced household policy (schema v8).

**Audit 2 (fix pass 2).** The security audit of fix pass 1, C2 and C1 (on db80570) found one Medium and three Low items, all fixed here. A removal found in the background exited inside the widget refresh's 500 ms debounce, so a revoked or deleted kid phone kept the kid's last widget drawing: the wipe now draws every placed widget blank with one synchronous push before the process exits, and startup does the same first whenever a removal is stored (N1, D-M7-81). "Sign in again" going up or down redraws the widget (N2, D-M7-83; the gate stays in memory, accepted). The prune watermark's gap check compared the server's watermark with this phone's own receive clock and counted any missing predecessor as pruned: pulled messages now keep their server stamp (schema 9, `MIGRATION_8_9`) and only server stamps are compared, with a missing predecessor counted only when the thread holds nothing or the cut reaches into its stored history (N3, D-M7-80, ADR-0011 §5). "Sign in again" takes the account e-mail, password and parent PIN, so it is `FLAG_SECURE` too (N4, D-M7-82, T15). Info items: `PromptParentConfirmation` gained seams and a policy test, and `PolicyAdaptersTest` checks that a setter without a policy row lets `NoHouseholdPolicyYetException` through and prunes nothing (I1); `SecureAreaTest` checks that a dialog inside an area inherits its flag (I6); the benchmark build types can no longer be bundled (`checkNotForPlay`, I3, D-M7-84); FakeBackend's watermark KDoc (I7) and PRIVACY's export wording on fetched media (I8) are corrected; the exported widget receiver is left as is and noted (I2, D-M7-85).
