# M8: Play release

Everything that stands between the merged M7 tree and a Play internal-track build: a published privacy policy and `security.txt`, the Play data-safety form prepared from the code, a security review checklist with evidence, release signing and versioning plumbing, a release workflow, store listing assets generated from the screenshot tests, the operator script the runbook promised, and the console and device steps only the owner can do. Base: `main` after M7.

Two halves:
- **Autonomous (this milestone's slices):** everything that can be built, generated, tested or documented from the repository.
- **Owner checklist (`docs/RELEASE_CHECKLIST.md`):** every step that needs the Play Console, the Firebase console, Vercel, a keystore, a real device or a legal decision. The run leaves each with exact commands and the values to paste; nothing is faked.

Constraints that shape the design:
- No keystore, service account or `google-services.json` is ever committed; the release build reads signing from environment variables / `~/.gradle/gradle.properties` and fails loudly when they are missing (`checkReleaseConfiguration` grows).
- The privacy policy is the single source: `docs/PRIVACY.md` renders to the hosted page; the data-safety answers are derived from the same document plus a code inventory, so they cannot drift.
- Claims the run cannot verify (network capture on a real device, Play Integrity against the real project, Nano on hardware) stay marked "unverified" in the checklist and the threat model; nothing is upgraded to "Implemented" without evidence.

## 1. Privacy policy page and disclosure
- `tools/privacy/render.py` (or a Gradle task) renders `docs/PRIVACY.md` → `server/public/privacy/index.html` (static, no scripts, system fonts, light/dark) and `server/public/.well-known/security.txt` (+ `/security.txt`), both served by Vercel from `server/public` (`vercel.json` rewrites exclude `/privacy`, `/.well-known`, `/robots.txt`). CI checks the rendered page is up to date with the Markdown (`npm run check:privacy`).
- PRIVACY.md finalised structurally: fix the stale claims (Cloud Storage → Firestore chunks; camera permission → system camera; export is a zip; Vercel log retention stated as "up to 30 days unless Vercel's retention is longer: see Vercel's policy"; Firebase Installations IDs and Play services listed under Technical data; the Play services receipt-scan event; TTS engine note), placeholders `{{CONTACT_EMAIL}}`, `{{DEVELOPER_NAME}}`, `{{POSTAL_ADDRESS}}`, `{{EFFECTIVE_DATE}}` filled from `docs/privacy.properties` (gitignored; example committed) at render time so the owner fills one file. `docs/SECURITY.md` (disclosure policy: scope, how to report, 90-day disclosure, no bounty) backs `security.txt`.
- The About screen gains "Privacy policy" and "Security and disclosure" rows opening the hosted URLs (`BuildConfig.PRIVACY_URL` from a Gradle property with a default to the production Vercel host), "Open-source licences" (AboutLibraries or a generated `licenses.html` from the Gradle dependency report — pick the one that needs no new verification entries beyond what is listed) and the version/build.

## 2. Data-safety form
`docs/DATA_SAFETY.md`: the Play form answered section by section (collected vs. shared, each data type, purpose, encryption in transit, deletion path, SDK disclosures: Firebase Auth/Firestore/App Check, Credential Manager, Play services ML Kit text recognition usage event, AICore/Play services model downloads) with a pointer to the PRIVACY.md section and the code location for each answer, and a generated inventory `tools/privacy/inventory.py` that lists permissions and third-party SDKs from the merged manifest and the runtime classpath so the form is checked against the build in CI (`checkDataSafetyInventory`: fails when a new permission or SDK appears without a `DATA_SAFETY.md` entry). D-M6-51's legal question is listed for the owner with the recommended answer (list the event as "app performance / diagnostics, collected, not shared beyond Google, optional").

## 3. Security review checklist
`docs/SECURITY_REVIEW.md`: every control in `docs/CONTROLS.md` with evidence links (test names, workflow names, doc sections), the "Known gaps" list refreshed, the accepted risks, and an explicit "verified on a real device / against the real project" column that is "No" for Play Integrity, Google sign-in, attestation chain, the AI network capture, voice notes, auto-stop, process death and the Nano path, each with the exact procedure for the owner (adb commands, `tcpdump`/`mitmproxy` steps for the capture, expected results). CONTROLS summary counts corrected and the stale rows updated (IA-16 remains Planned until the console step). THREAT_MODEL status line and T11/T33 wording. ADR-0003's "debug App Check provider never ships" gets a CI check: a release-classpath test that `DebugAppCheckProviderFactory` is absent (`checkReleaseAppCheck`).

## 4. Signing, versioning, release configuration
- `signingConfigs.release` from `SPROUT_UPLOAD_KEYSTORE`, `SPROUT_UPLOAD_KEYSTORE_PASSWORD`, `SPROUT_UPLOAD_KEY_ALIAS`, `SPROUT_UPLOAD_KEY_PASSWORD` (env or Gradle properties); release uses it when present, otherwise `bundleRelease` fails in `checkReleaseConfiguration` (which also checks `sprout.googleServerClientId`, the privacy URL and the keystore); `tools/release/create-upload-keystore.sh` (documented, owner runs it; prints the SHA-1/SHA-256 to register for Google sign-in and Play Integrity).
- Versioning: `versionName` from the latest `v*` git tag (fallback `0.1.0-dev`), `versionCode` from `git rev-list --count HEAD` or a `-PversionCode=` override; documented.
- R8: a release smoke test that the obfuscated APK starts (Robolectric cannot; instead `assembleRelease` + a `checkReleaseMapping` task that the mapping file exists and that Hilt/Room/Glance keep rules produced no "Missing class" warnings) and a proguard rules review (the file is empty; add rules only if `assembleRelease` warnings require them).
- `.github/workflows/release.yml` (manual `workflow_dispatch` with the tag): builds `bundleRelease` with the secrets (`GOOGLE_SERVICES_JSON_B64`, keystore base64 + passwords, `SPROUT_FUNCTIONS_BASE_URL`, `SPROUT_GOOGLE_SERVER_CLIENT_ID`, `SPROUT_PRIVACY_URL`), runs the gate, uploads the AAB and mapping as artifacts, optionally publishes to the internal track with Gradle Play Publisher when `PLAY_SERVICE_ACCOUNT_JSON` is set (documented, off by default). Secrets are never echoed; the workflow is pinned by SHA and read-only except the artifact upload. It is written and dry-run-validated with `act` or a syntax check only; running it is the owner's step.

## 5. Store listing assets
`tools/store/` (Python, run locally and documented): composes Play-valid phone screenshots (1080×2340, 9:19.5, PNG ≤ 8 MB) and 7"/10" tablet screenshots from the committed goldens (selected list in `tools/store/listing.yaml`: parent dashboard, kid wallet per tier, chores, chat, games, time bank, settings) on a plain background with a short caption per image (light and dark sets), exports the 512×512 icon and the 1024×500 feature graphic from the launcher vectors, and writes `play/listing/en-GB/{title,short_description,full_description}.txt` (≤ 30 / 80 / 4000 chars) plus a `play/listing/README.md` with the upload order. No listing is uploaded by the run.

## 6. Operator script and ops items
`server/scripts/operator.ts` (Admin SDK; run only by the owner with the service account): `recover-household` (D-M3-42: re-admit a new parent device for a household whose parent phones are gone, with an audit record), `delete-household --hid` (RUNBOOK §4, e-mail deletion requests), `export-household`, `prune-expired` (TTL fallback for `deletionRecords` 12 months and server logs note); tests against the emulator; RUNBOOK §2/§4 updated. `npm audit --audit-level=high` in the backend CI job for `server` and `firestore` (SC-4) with a suppression file procedure. FIREBASE.md production checklist extended with Play App Signing, SHA registration, OAuth web client id, Play Console ↔ Cloud project linking, App Check enforcement for Firestore with the rules smoke test, Firestore TTL setup, budget alerts.

## 7. Owner checklist (`docs/RELEASE_CHECKLIST.md`)
Ordered, with commands and expected outputs: create the upload keystore; register SHA-1/SHA-256 (debug and upload) for Google sign-in and Play Integrity; create the OAuth web client id and set `sprout.googleServerClientId`; fill `docs/privacy.properties` and render; deploy the server (privacy page live) and verify `https://<host>/privacy` and `/.well-known/security.txt`; enable App Check enforcement for Firestore and run the smoke test; Play Console: app, 18+ audience, data-safety form from `DATA_SAFETY.md`, privacy URL, content rating, target audience, listing assets from `play/listing`; run `release.yml` with the secrets → internal track; device verification list from `SECURITY_REVIEW.md` (network capture incl. a receipt scan, Play Integrity, Google sign-in, voice notes, auto-stop, process death, Nano on a Pixel 9+); closed → production promotion criteria. Each item has a checkbox and a "evidence to paste into SECURITY_REVIEW.md" line.

## 8. Docs

## 9. Verification

## 10. Slices
- **A** (server + ops): privacy/security.txt serving, operator script, npm audit, FIREBASE/RUNBOOK updates.
- **B** (build + release): signing/versioning/release-config checks, release workflow, R8 mapping check, App Check release check, About screen rows (feature/settings), `BuildConfig.PRIVACY_URL`.
- **C** (docs + assets): PRIVACY finalisation + renderer + inventory + DATA_SAFETY + SECURITY_REVIEW + RELEASE_CHECKLIST + store assets tooling + README/PLAN/CONTROLS/THREAT_MODEL updates.
- Then reviewer + security auditor (release configuration, secrets handling in the workflow, privacy claims vs. code), fix pass, gate, PR.

## Out of scope
Uploading anything to Play or the consoles, creating real keys or accounts, legal review itself, Crashlytics, paid plans.

## Decisions
D-M8-1 privacy page rendered from PRIVACY.md and served by the Vercel server; D-M8-2 data-safety answers derived from the policy plus a CI-checked manifest/classpath inventory; D-M8-3 signing from environment/Gradle properties only, keystore created by the owner with a script; D-M8-4 version from git tags and commit count; D-M8-5 release workflow manual, artifacts only, Play publishing optional behind a secret; D-M8-6 store screenshots composed from goldens, not device captures; D-M8-7 operator script in `server/scripts`, owner-run with the service account; D-M8-8 unverifiable claims stay "unverified" with an owner procedure; D-M8-9 licences screen approach; D-M8-10 `npm audit` at high severity in CI.
