# M2 — Chores, rewards, allowance, savings, parent lock

Scope from `docs/PLAN.md` M2 plus the M2 items of ADR-0004. Everything here is implemented on branch `m2/chores-rewards-lock` and lands as one PR.

## Domain (pure Kotlin)

New module `core/domain-household` (plugin `sprout.jvm.library`, depends on `core/model`, `core/domain-ledger`, `core/time`). Models live in `core/model`; rules and schedules live here.

- `Chore(id: ChoreId, householdId, kidId, title (≤80), description (≤500, optional), reward: ChoreReward(money: Money?, minutes: Money?) at least one, schedule: ChoreSchedule, createdAt, archived)`.
- `ChoreSchedule`: `Once(dueOn: CalendarDate?)`, `Daily(daysOfWeek: Set<DayOfWeek>)`, `Weekly(dayOfWeek)`, `Monthly(dayOfMonth 1..28)`. `ChoreOccurrence(choreId, dueOn: CalendarDate)` is derived, never stored. `ChoreScheduler.occurrences(chore, from, to)` and `nextDue(chore, after)`; pure, tested against a fixed calendar.
- `ChoreSubmission(id, choreId, dueOn, kidId, submittedAt, note (≤200), photoRef: PhotoRef?, status: SUBMITTED | APPROVED | REJECTED, decidedAt, decidedBy: UserId?, rejectionReason (≤200))`. Status precedence for sync: `APPROVED` > `REJECTED` > `SUBMITTED`. An approval produces exactly one `ChoreRewarded` ledger event per reward currency (`choreId` + `dueOn` make the submission id deterministic, so re-approval is idempotent).
- `Reward(id: RewardId, householdId, title (≤80), kind: SCREEN_TIME | TREAT | OUTING | OTHER, cost: Money, currency: Currency, minutesGranted: Int? (only for SCREEN_TIME), active, forKids: Set<KidId> (empty = all))`. Purchase → `RewardPurchased` on the fiat MAIN account; a `SCREEN_TIME` reward additionally credits minutes via a `TimeBankCredited` ledger event (new event type, parent-only by default but authorised when it references an accepted `RewardPurchased` eventId; rule: amount == reward.minutesGranted).
- `AllowanceSchedule(kidId, amount: Money, currency, cadence: WEEKLY(dayOfWeek) | MONTHLY(dayOfMonth), startsOn, active)`. `AllowancePlanner.due(schedule, lastPaidOn, today): List<CalendarDate>` (catch-up capped at 8 periods). Each due date → one `AllowancePaid` event with `periodKey` (e.g. `2026-W45` / `2026-11`) so re-planning is idempotent.
- `SavingsGoal(id, kidId, title (≤80), target: Money, createdOn, achievedOn?)`. Progress is a projection over the SAVINGS account balance.
- `InterestPolicy(householdId, annualRateBasisPoints 0..2000, accrualDay: dayOfMonth 1..28)`. `InterestPlanner.due(policy, balanceHistory, lastAccruedOn, today)` → `InterestAccrued` events using `InterestCalculator`.
- `PendingParentAction`: a queue of parent-only ledger events that were planned by a scheduler (allowance, interest) but cannot be signed without the parent key; drained when the parent unlocks (ADR-0004, "signed at next parent unlock").

## Ledger envelope v2 (core/domain-ledger)

- `schemaVersion = 2`: adds `parentSignature: String?` (base64, ECDSA P-256 by the parent auth key over `"sprout/ledger-event-parent/v2" || 0x00 || canonical`). Parent-only events (`ChoreRewarded`, `AllowancePaid`, `ManualAdjustment`, `InterestAccrued`, `OverdraftCompensated`, `TimeBankCredited` unless reward-referenced) must carry it when the household policy `requireParentSignature` is true (default true once a parent key exists). v1 events remain valid for reading.
- `LedgerRules` gets `ParentSignatureMissing`. Verification of the parent signature happens in the data layer against the household's registered parent keys (M3); in M2 the local writer signs and verifies against its own parent key.
- `LedgerWriter.append` gains an overload for parent-only events that takes a `ParentAuthorization` (an opened `Signature` from a successful `BiometricPrompt` with `CryptoObject`), so the feature layer must prompt before calling.

## Crypto (core/crypto)

- `AndroidKeystoreParentAuthKeyStore`: new alias `sprout.parent.auth.v2`, `setUserAuthenticationParameters(0, AUTH_BIOMETRIC_STRONG)`, `setInvalidatedByBiometricEnrollment(true)`. `ParentSigner.sign(authorization, payload)`.
- `ParentAuthAvailability`: STRONG_BIOMETRIC_AVAILABLE | NOT_ENROLLED | NO_HARDWARE. Devices without strong biometrics: events are written without `parentSignature` and the household policy records `parentSignatureRequired = false` with a visible warning in settings (pending decision D-M2-1).
- PIN pepper: `KeystoreHmacPepper` (alias `sprout.pin.pepper.v1`, HMAC-SHA256 key, no user auth); `Argon2idPinHasher` input = HMAC(pin). Format version `v2$argon2id-pepper$...`; v1 hashes verify and are flagged for rehash.
- Lockout: `PinLockoutPolicy` persists served time (`SystemClock.elapsedRealtime` + boot id) so a reboot does not reset it; after the cap, a biometric re-auth is required instead of waiting.

## Data (core/database)

Tables: `chores`, `chore_submissions` (unique `(choreId, dueOn)`), `rewards`, `allowance_schedules`, `savings_goals`, `interest_policy` (single row per household), `pending_parent_actions`, `photos` (local file refs only; bytes encrypted with the household AEAD key placeholder in M2: `Aead` with a per-install key from `SecretStore`; real household key in M4). Schema version 2 with a migration from 1 and a migration test. Repositories: `ChoreRepository`, `RewardRepository`, `AllowanceRepository`, `SavingsGoalRepository`, `InterestPolicyRepository`, `PendingParentActionRepository`. Every document write also writes an outbox row (`kind = DOCUMENT`, `docType`, `docId`, LWW `lamport`).

## Features

- `feature/lock`: first-run PIN setup (6 digits, confirm), PIN entry with lockout feedback, biometric unlock (`BiometricPrompt`, `BIOMETRIC_STRONG`), `ParentSession` state (locked/unlocked, auto-lock after 2 min in background), `RequireParent { }` composable gate, `FLAG_SECURE` on parent screens, kid-mode exit gate. The parent session is only an app-level gate; money events still need per-event parent authorisation.
- `feature/chores`: parent list/create/edit/archive chores, assign to kid; approvals inbox (submissions with photo preview, approve/reject, each approval prompts the parent authorisation); kid "Today" per tier: Seedling picture cards (max 3, one-tap Done + confetti), Sprout list with due dates, rewards, note + photo; Sapling list plus "propose a chore" (creates a chore in `PROPOSED` state for the parent to accept).
- `feature/wallet` shop: rewards catalogue per tier (Seedling picture tiles with can/can't afford, Sprout prices + "days until", Sapling full catalogue + wishlist), purchase flow (kid-authored `RewardPurchased`; screen-time rewards credit the time bank).
- `feature/settings` (minimum): kids & tiers (edit name, birth month, tier override), allowance per kid, interest policy, savings goals per kid, parent PIN change, parent-signature policy status.
- `feature/parent-home`: dashboard cards: pending approvals count, kids' balances, next allowance dates, anomalies; entry to each feature.
- `feature/timebank`: unchanged in M2 except that `TimeBankCredited` feeds it.
- `app`: parent/kid mode switch (parent mode behind the lock; kid mode picks a kid and stays until exit gate), navigation, `WorkManager` periodic planner (daily) that plans allowance and interest into `pending_parent_actions`.

## Screenshot tests

Roborazzi set up via a convention plugin (`sprout.android.screenshot`), one `@Preview`-driven screenshot test per screen × tier × key state for wallet, shop, chores today, lock. Golden images committed under `src/test/screenshots`; CI compares and uploads diffs on failure.
