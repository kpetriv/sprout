# M5: Brain games

Three short games that earn small credits: **arithmetic**, **pattern memory** and **word scramble**. Difficulty follows the kid's UI tier. A play produces one signed `GamePlayed` ledger event authored by the kid; the existing daily cap (`LedgerPolicy.dailyGameCap`, projection `applyGame`) bounds what any kid device can credit per day. Base: `main` after M4 (shortcut bar, `ReadAloud` TTS, `Confetti`).

## 1. Game logic (`core/games`, pure Kotlin, KMP-ready)

New JVM module `core/games` (same convention plugin as `core/domain-ledger`), package `dev.kpetriv.sprout.core.games`. No Android, no coroutines, no I/O. Everything deterministic from a `kotlin.random.Random` seed so tests replay sessions.

- `GameKind { ARITHMETIC, MEMORY, WORDS }`, `Difficulty { SEEDLING, SPROUT, SAPLING }` (one per tier; a tier plays only its own difficulty), `GameId(kind, difficulty)` with wire form `"<kind>.<difficulty>"` lower case (`arithmetic.sprout`), `GameId.parse(String): GameId?`. `GameCatalogue.forTier(tier): List<GameKind>`: Seedling gets ARITHMETIC and MEMORY only (word scramble is hidden, never shown broken), Sprout and Sapling get all three.
- `GameSession(gameId, seed)` → `rounds: List<Round>` (Seedling 5, Sprout 8, Sapling 10). Round types:
  - `ArithmeticRound(prompt: Expression, answer: Int, choices: List<Int>)`. Seedling: counting (1–10 dots, "How many?") and add/subtract within 10, four picture-friendly choices. Sprout: add/subtract within 100, tables 2–12. Sapling: mixed two-step expressions, negatives, division with whole results; typed answer (no choices).
  - `MemoryRound(sequence: List<Symbol>, distractors: List<Symbol>)`. Seedling: 3–5 pictures (emoji from a fixed 12-symbol set); Sprout: 4–7 colours/shapes; Sapling: 5–9 with 2 distractors shown among the choices.
  - `WordRound(word: String, scrambled: String, hint: String?)` from a built-in word list (`WordList`, ~300 common English words we write ourselves, grouped by length: Sprout 4–6 letters with a one-word hint, Sapling 6–9 letters, no hint). The scramble is never equal to the word.
- `GameScorer.score(gameId, outcomes: List<RoundOutcome>): Score` where `RoundOutcome(correct: Boolean, elapsedMs: Long)` and `Score(correct: Int, total: Int, perfect: Boolean, timedBonus: Boolean)`. Sapling may enable **timed mode** (`timed = true` in the session): `timedBonus` when every round answered within its limit (arithmetic 8 s, memory 10 s, words 15 s).
- `GameCredit.earned(gameId, score): Money?`: `null` for an unknown id or `score.correct !in 0..rounds(gameId)`; otherwise `correct × 1` minor unit, `+3` for `perfect`, `+2` for `timedBonus`, capped at **15** per play. This is the only place that turns a score into money; the ledger rule in §2 re-derives it.

## 2. Ledger rule (`core/domain-ledger`, `core/database`, verifier)

`GamePlayed` keeps its v2 shape (`gameId`, `score`, `playedOn`); no schema bump, no rules change (the rules already whitelist those keys with `gameId ≤ 128`, `score` int, `playedOn ≤ 32`). New static rules in `LedgerRules`:

- `gameId` must parse as a `GameId` (`Violation.UnknownGame(gameId)`); `score` must be within `0..rounds(gameId)` (`Violation.ScoreOutOfRange`); `amount` must be `≤ GameCredit.earned(gameId, score)` (`Violation.GameCreditTooHigh(earned, requested)`). Less than earned is allowed so the author can clamp to the remaining daily cap. `core/domain-ledger` therefore depends on `core/games` (pure Kotlin → fine for KMP).
- `playedOn` window (threat model T12 follow-up): a pulled event whose `playedOn` is later than the `serverReceivedAt` date + 1 day, or earlier than it − 7 days, is quarantined with `PLAYED_ON_OUT_OF_RANGE` in `RemoteEventVerifier`; locally authored events are validated against the device date with the same window. Offline play up to a week still syncs; backdating is bounded to seven days of cap.
- `ViolationCodec` and `AnomalyMapper` (`core/database`) and `feature/parent-home` `RejectionReason` gain the new values; `LedgerPropertyTest.deltas`, `CanonicalEncoderTest.allEventTypes`, `HashChainTest.payloadMutations` (add `GamePlayed` mutations: gameId, score, amount) are extended. The daily cap stays the hardcoded default (50 minor units of the fiat currency per kid per day, D-M5-4); games credit the **fiat MAIN account only**.

## 3. Use case (`core/database/usecase`)

`PlayGameUseCase(kidId, gameId, score): GameCreditResult` modelled on `PurchaseRewardUseCase`: computes `earned`, reads today's remaining cap from `ledger.projection().dailyGameCredits(kid, today, fiat)`, clamps `amount = min(earned, remaining)`; if `amount == 0` returns `CapReached` without appending; otherwise `writer.appendAsKid(kidId, fiatMain.id) { GamePlayed(it, fiat, amount, gameId.wire, score.correct, today) }` → `Credited(amount, remainingAfter)`, `NoAccount`, `Refused(AppendResult)`. `today` from `HouseholdCalendar.today()`. `GameCapReader.observeRemaining(kidId): Flow<Money>` for the hub screen (projection-backed, updates on ledger changes and midnight via `todayUpdates()`).

## 4. Feature (`feature/games`)

Replace the placeholder. Plugins `sprout.android.feature` + `sprout.android.screenshot`. Depends on `core/games`, `core/ui`, `core/designsystem`, `core/time`, `core/domain-ledger` (Money); **not** on `core/database` (ports pattern like `feature/timebank`).

- `GamesPorts.kt`: `GameCreditSubmitter { suspend submit(kidId, gameId, score): GameCreditResult }`, `GameCapSource { observeRemaining(kidId): Flow<Money> }`, `GameSeedSource` (default `Random.Default`; tests inject). Money shown with `rememberMoneyFormatter`.
- Screens, each switching on tier inside `ProvideKidTier` with one `UiState`:
  - `GamesHubRoute(kidId, tier, onBack, readAloud)`: tiles per `GameCatalogue.forTier`, remaining credit today ("You can still earn 23p today"; Seedling: coins graphic, no decimals, read-aloud on tap), cap-reached state ("Come back tomorrow, you can still play for fun").
  - `GamePlayRoute(kidId, tier, kind, onFinished)`: one composable per kind (`ArithmeticGame`, `MemoryGame`, `WordGame`), big tier-scaled controls, progress "3 of 8", Seedling read-aloud of each prompt, Sapling "Timed" toggle on the start card. Memory shows the sequence for 700 ms per symbol then hides it. The `GameViewModel` holds `GameSession` + outcomes in `SavedStateHandle` (seed + index) so rotation and process death resume the round, never re-roll it.
  - `GameResultScreen`: score, credit earned ("+8p"), `Confetti` (moved from `feature/chores` to `core/ui` as `public`), "Play again" / "Done"; when clamped or capped it says so in tier language.
- Playing when the cap is reached is allowed; `submit` returns `CapReached` and the result screen shows "for fun" (D-M5-7).
- Accessibility: every choice has a content description; the memory sequence is also announced via live region when TalkBack is on (symbols have names).
- Screenshot tests `GamesScreenshotTest` with `captureTiers`: hub ready, hub cap reached, arithmetic round (choices / typed), memory showing, memory answering, word round, result credited, result capped. Word scramble goldens exist only for Sprout and Sapling.
- Unit tests: `core/games` generators (seeded replay, answer always among choices, scramble ≠ word, word list bands), scorer, `GameCredit` table and cap; feature ViewModels with fakes (resume after process death, submit paths).

## Out of scope

Parent-configurable daily cap (M7 settings), minutes-currency game credits, leaderboards or sharing, cloud word lists, AI-generated puzzles (M6 may add hints), logic puzzles beyond the three games.
