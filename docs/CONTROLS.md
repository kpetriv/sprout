# Sprout controls matrix

- **Status:** First version (M3, 2026-11-03). Reviewed at the end of each milestone with the [threat model](THREAT_MODEL.md) and before release (M8).
- **Scope:** the Android app, the Sprout server (`server/`), the Firestore rules (`firestore/`), and the repository and CI that build them.
- **Purpose:** the controls a SOC 2 Type I style review would ask about (PLAN "Security bar"), each tied to where it is implemented and what shows it works. This is a self-assessment for a portfolio project, not an audit report.
- **Related:** [threat model](THREAT_MODEL.md), [privacy policy draft](PRIVACY.md), [incident runbook](RUNBOOK.md), [Firebase backend](FIREBASE.md), ADRs [0003](adr/0003-security-model.md), [0004](adr/0004-parent-authorisation-and-device-identity.md), [0006](adr/0006-sync-protocol-and-document-envelope.md), [0007](adr/0007-identity-linking-and-device-registry.md).

## How to read it

**Criteria** are the 2017 Trust Services Criteria (revised points of focus 2022): **CC6.x** logical and physical access, **CC7.x** system operations (detection, monitoring, incident response), **CC8.1** change management, **CC9.2** vendors, **A1.x** availability, **C1.x** confidentiality, **P1–P8** privacy (notice, choice, collection, use and retention, access, disclosure, quality, monitoring).

**Status:** **Implemented Mx** (in the code or repository settings since milestone x, with the evidence listed); **Partial Mx** (implemented, with the named gap); **Planned Mx** (not built yet). Evidence names are test names (`file: "test name"`) or CI jobs; Kotlin tests are named by class. "CI build" is the required job `Build, static analysis, unit tests`; "CI backend" is the job `Backend: rules and server tests` (not required yet, D-M3-11).

### Known gaps (M3)

1. **Parent-key attestation exercised on the emulator only** (IA-19). The app now creates the parent key with the server's challenge and sends its chain; it has been verified end to end only with the Android emulator's software chain (recorded `NONE` in emulator mode), not with a hardware TEE/StrongBox chain against production.
2. **No real attestation fixture** (IA-8): the Google-rooted path is tested only with a self-generated chain.
3. **Play Integrity and Google sign-in unexercised** (IA-1, IA-15) and **App Check not enforced on Firestore** (IA-16, M8).
4. **Vercel deployment, service account and secrets unverified** (AV-8, IA-21, SE-2); **Firestore location unverified** (DP-11).
5. **Backend CI job not required** (CM-3); **no npm vulnerability scanning** (SC-4).
6. **No server-side backups** on Spark (AV-7); **no alerting** (LM-6).
7. **Retention not fully enforced**: TTL policies are console steps and `deletionRecords` has no expiry (DP-7).
