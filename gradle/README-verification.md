# Dependency verification

`verification-metadata.xml` records a SHA-256 checksum for every artifact the build downloads, and Gradle fails the build if anything differs. The file is generated, so it carries no comments. Renovate branches get it regenerated automatically by `.github/workflows/verification-metadata.yml`. After adding or bumping a dependency by hand, regenerate it with `./gradlew --write-verification-metadata sha256 help build detekt lint test --no-configuration-cache` (`help` alone misses artifacts resolved while tasks run, such as aapt2 and the Detekt and Lint classpaths) and review the diff before committing: new entries should match the change you made and nothing else, because a checksum written this way is trusted on first use. Dependency-Check also reads POMs the build never downloads; append `dependencyCheckAnalyze --continue` to that command to record them (the analysis itself still needs `NVD_API_KEY` and fails without it, but the checksums are written). Gradle only adds entries; do not regenerate from an empty file on a warm local cache, because parent POMs and BOMs that a cold CI runner downloads would then be missing.
