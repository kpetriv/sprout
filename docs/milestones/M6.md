# M6: On-device AI

`core/ai` becomes real: one `AiGateway` with four typed tasks, a **Gemini Nano** implementation on the ML Kit GenAI Prompt API (AICore) where the device supports it, and a **rules** implementation that runs everywhere. Every feature works identically on the emulator, where only the rules path runs. Nothing leaves the device for AI (PLAN.md §On-device AI, PRIVACY.md). Base: `main` after M5.

Constraints that shape the design:
- AICore inference is allowed only while the app is the foreground app and may answer `BUSY`; the model is downloaded by the system on Wi-Fi after the app asks. Every AI call therefore runs from a ViewModel, has a timeout, and has a rules result ready.
- Model output is untrusted text: it is parsed with structured output, validated against hard bounds, and replaced by the rules result when it fails validation. The kid's or parent's text is always data inside a prompt, never an instruction.
- The Prompt API is beta (ML Kit GenAI, January 2026; structured output July 2026). Artifacts: `com.google.mlkit:genai-prompt` for text tasks; `com.google.android.gms:play-services-mlkit-text-recognition` (unbundled, on-device) for receipts. Both need `gradle/verification-metadata.xml` regenerated per `gradle/README-verification.md`.

## 1. `core/ai`

Android library with Hilt (`sprout.android.library` + `sprout.hilt`), package `dev.kpetriv.sprout.core.ai`.

- `AiAvailability { AVAILABLE, DOWNLOADABLE, DOWNLOADING, UNAVAILABLE }` plus `AiStatus(availability, reason: String?)`; `AiGateway`:
  - `suspend fun status(): AiStatus`
  - `suspend fun requestDownload(): Boolean` (asks AICore; the system downloads on Wi-Fi)
  - `suspend fun kindness(text: String, tier: KidUiTier): KindnessVerdict` → `Ok | Nudge(suggestion: String?)`; suggestion ≤ 200 code points, same language register, never echoes insults.
  - `suspend fun suggestChores(band: AgeBand, existingTitles: List<String>, currency: Currency.Fiat): List<ChoreSuggestion(title, description, money: Money?, minutes: Long?, schedule: SuggestedSchedule)>` (3–5 items, titles ≤ `MAX_TITLE_LENGTH`, rewards within `LedgerPolicy.maxAmount`, no duplicates of existing titles).
  - `suspend fun weeklySummary(facts: WeeklyFacts): String` (2–4 sentences, ≤ 600 code points; every number in the text must appear in `facts`, otherwise the rules text is used).
  - `suspend fun receiptPrefill(jpeg: ByteArray): ReceiptPrefill?` → `(amount: Money?, merchant: String?)` (text recognition + rules parsing of the largest "total"-labelled amount; merchant = first line ≤ 40 chars; no model call).
- `RulesAiGateway` (pure Kotlin, deterministic, tested): kindness lexicon we write ourselves (insult/profanity stems by category, "you are/you're + negative", shouting = ≥ 8 letters all caps, ≥ 3 `!`), suggestion templates ("Could you say it in a kinder way? For example: …"); chore catalogue per `AgeBand` (≥ 12 per band with default rewards and schedules); weekly summary template per facts; receipt parser.
- `GeminiNanoAiGateway`: Prompt API with system instructions + structured output (JSON schema per task), temperature low, timeout 2 s (kindness) / 6 s (suggestions, summary); maps `BUSY`, not-available and parse/validation failures to the rules result; `status()` from `checkFeatureStatus`.
- `AiRouter : AiGateway` chooses per call: Nano when `AiPreferences.enabled` and status `AVAILABLE`, else rules; always returns within the timeout. `AiPreferences` (DataStore in core/ai): `enabled` (default true), `downloadConsent: Boolean` (default false; the settings row asks once before `requestDownload`).
- Validators in `AiOutputRules` (pure): lengths, code points, numeric-consistency for summaries, reward bounds, title dedupe, no URLs, no e-mail/phone patterns.
- Logging: never the text; only task name, path (nano/rules), latency bucket and failure kind at DEBUG; nothing in release (Timber tree rule). All result types redact `toString`.
- Hilt `AiModule`: binds `AiGateway` to `AiRouter`; provides `RulesAiGateway`, `GeminiNanoAiGateway`, `AiPreferences`.

## 2. Facts for the summary (`core/database`)

`WeeklyFactsUseCase(week: IsoWeek = current)`: per kid → earned by kind (chores, allowance, games, interest), spent (rewards, time bank minutes used), savings transfers, chores submitted/approved/rejected, games played, anomalies; household totals. Computed from stored events and submissions by `HouseholdCalendar.dateOf(createdAt)`; pure Kotlin `WeeklyFacts` model in `core/domain-household`. Tests with the ledger fixtures. No schema change. The dashboard shows the current ISO week so far and last week.

## 3. Features (ports in each feature, adapters in `app`, as in M4)

### 3.1 feature/chat
`OutgoingMessageFilter` is bound in `app` to the gateway's `kindness` (delete the `None` provider in the feature module; keep `None` for tests). Timeout and fail-open stay in the feature (`withTimeoutOrNull(2.5 s)`), `checking` shows a small progress indicator. A suggestion accepted through `NudgeUseSuggestion` is sent without a second check when the draft is still exactly the suggestion (D-M6-2). New state copy when AI is downloading/unavailable is NOT shown to kids (the rules path is silent). Goldens: `chat_kid_checking` re-recorded if the indicator changes.

### 3.2 feature/chores
Port `ChoreSuggestions { suspend fun suggest(kidId, band, existing): List<ChoreSuggestionUi> }`; `KidOption` gains `band: AgeBand`. In the editor a "Suggest chores" button (parent only) opens a sheet with 3–5 cards; tapping one fills title, description, money/minutes and schedule through the existing events (never saves). Loading/empty/error states; goldens `chores_editor_suggestions_{light,dark}`.

### 3.3 feature/parent-home
Port `WeeklySummarySource { fun observe(): Flow<WeeklySummaryUi> }` → `Loading | Ready(text, week, path: NANO|RULES, generatedAt) | Unavailable`. `WeeklySummaryCard` renders the text, "This week so far" / "Last week" toggle, a small "On-device" chip, and a "Download the on-device model" action when `DOWNLOADABLE` and consent is off (routes to the settings row). Fails soft. Goldens `parent_home_summary_{light,dark}` (+ busy dashboard re-recorded).

### 3.4 feature/wallet
`AdjustmentUi.prefill: AdjustmentPrefill?`; "Scan a receipt" button in the manual adjustment sheet (parent only) using a `ReceiptScanner` port (`suspend fun scan(): ReceiptPrefill?`, app implements picker + gateway); prefill fills amount (DEBIT) and reason `"Receipt: <merchant>"` truncated to 200; the parent still reviews and signs. The reason is plaintext in the ledger (PRIVACY.md row): the sheet says so under the button. Goldens `wallet_adjustment_prefilled_{light,dark}`.

### 3.5 feature/settings
`SettingsSection.AI` ("On-device AI": status line, enable switch, "Download model on Wi-Fi" consent row with explanation, "What it is used for" text). Port `AiSettingsSource`. Goldens `settings_ai_{light,dark}`.

### 3.6 app
Adapters for the five ports; `AiModule` wiring; `AppInitializer` step that refreshes `AiStatus` once (no download without consent); photo picking for receipts via a shared `core/ui` `PickedImageReader` extracted from chat's `ContentResolverPickPhoto` (chat re-pointed, chores untouched).

## Out of scope
Cloud AI of any kind, AI in Seedling chat, AI-generated puzzles for games, persisted summaries/history, parent-visible kindness reports (never), non-English prompts (rules lexicon is English; the Nano path follows the device locale).

## Decisions
D-M6-1 gateway + router + rules-first; D-M6-2 accepted suggestion sends without re-check; D-M6-3 summary facts are computed deterministically and the model only rewrites, numbers validated; D-M6-4 curated chore catalogue is the fallback and the validator for model suggestions; D-M6-5 receipts use on-device text recognition (unbundled Play services model), merchant goes into the plaintext reason only after parent review; D-M6-6 download consent flag, default off, AI enabled by default where present; D-M6-7 no AI output persisted; D-M6-8 Prompt API (beta) chosen over the per-feature Summarization/Rewriting APIs (one dependency, structured output); D-M6-9 Nano path unverified on hardware until a Pixel run; D-M6-10 timeouts 2.5 s / 6 s.

## As built (2026-11-04)

The spec above is kept as written. What was built differs from it as described in the D-M6 rows of `docs/DECISIONS-PENDING.md` and in ADR-0010.

**Audit 1 and review (fix pass 1).** Audit H1 (ML Kit's usage-metrics uploader) is fixed: the app manifest removes datatransport's CCT backend, so no ML Kit metrics leave the app, and `:app:checkMergedManifestForTelemetry` (part of `check` for debug and release) fails the build if it comes back (D-M6-33; the permissions that remain are D-M6-50). Audit M2 is fixed: a kid's own linked phone uses the rules for the kindness check whatever its local switch says (the router's `AiContext`, provided by the app from the session), and the settings say the switch covers this phone only (D-M6-34, D-M6-49). Audit M1 and review M4 (the summary's number check) are fixed as D-M6-35; audit L2 is kept as D-M6-36. Review M1 to M3 and M5 (kindness lexicon, negation across clauses, apologies flagged as hostile, "Sub-total" read as the total) are fixed in `core/ai` (D-M6-37, D-M6-40). Review M6 is fixed: every AI call site treats a `CancellationException` from ML Kit while its own coroutine is active as a failure and resets `checking`, the chore sheet's Loading and `scanning` in a `finally` (D-M6-45). Review M7 is fixed: the chat field is disabled while the check runs and the checked text is the text sent (D-M6-46). The Lows taken in this pass: audit L3 (no download offered or started while AI is off, D-M6-49), audit L5 and review L14 (a late receipt prefill keeps the parent's edits, Save waits for the scan, a merchant without a total says "No total found", D-M6-47), review L13 (live regions, D-M6-48), and the `core/ai` and weekly-facts Lows (D-M6-37 to D-M6-42).
